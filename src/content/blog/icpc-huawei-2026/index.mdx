I made 10k USD by doing essentially nothing. Ok, not really. Claude and Codex carried me by implementing essentially all the code that took me to 3/4,428 in the ICPC Huawei Challenge. I spent two weeks steering their experiments and questioning the results.

This was my first optimization contest. For most of the two weeks, the workflow felt reproducible by anyone with access to the same tools, so third place was a surprise. The experiment logs make it possible to examine which interventions changed the search and which only generated more submissions.

*All timestamps are in Pacific Daylight Time (UTC−7).*

## Agent coordination

*August 14-28, 2026*

Huawei's task was online scheduling for disaggregated LLM inference across an edge machine and remote workers. The objective combined throughput and latency. Twenty-two preliminary tests provided feedback, but only the last positive-scoring submission would run on the twenty frozen finals tests.

Initially, Claude managed the experiment queue while Codex audited the scheduler in a separate checkout. Codex ran on my Linux machine and connected over SSH to my Mac, where Claude Code was running. Both agents polled an [append-only Markdown channel](https://github.com/seraph27/icpc-huawei-2026/blob/main/docs/SYNC_CLAUDE_CODEX.md): `ASK` and `ANSWER` entries tracked requests; `CLAIM` and `VERIFY` entries separated reported gains from reproduced results. They could communicate directly through the Mac checkout, with Git synchronization available between copies.

The initial audit brief focused on isolated, reproducible failures:

> Identify a scheduler failure and construct a minimal reproducer. Evaluate the smallest fix independently, in a separate workspace, so Claude's experiment queue can continue.

During the first night, the score rose from 13,286 to roughly 16,110. Codex found another 168 points, but three submissions exceeded Codeforces's 65,535-character source limit. Claude implemented a source shrinker and checked behavioral equivalence. The compressed build scored 16,278.897 and reached rank 3.

## Search stagnation

*August 19-22, 2026*

By August 19, both agents were concentrating on test six for gains of 0.247 and 0.111 points. The working channel already documented its low marginal return. More compute was producing local variations of the same scheduling policy.

The next instruction broadened the search:

> Broaden exploration beyond test six. Evaluate alternative scheduling policies and stop spending the whole night on one idea. Prioritize improvements likely to generalize to the hidden tests.

This changed the assignment without defining a rejection criterion. The agents continued producing nearby variants. By August 22, a stop hook even prevented the session from ending below rank 1. Basically “Claude, make no mistakes” with a loop around it.

Four days before the contest, [Anthropic published a mathematical research story](https://www.anthropic.com/research/riemann-zeta) where the human mostly told Claude to “keep going” and “believe in yourself.” Its footnote says similar encouragement helped with a Jacobian-conjecture result. Apparently telling the clanker to try harder now has a research citation.

A later research brief specified how to evaluate competing hypotheses:

> Give fresh agents the measurements and scorer without the accumulated hypotheses. Explore mechanisms the current solution cannot express. Report per-instance deltas and require independent reproduction of promising results.

One fresh-context experiment gained 1.580 points on the judge. All agents still used the same test generator, so separate conversations could reproduce the same evaluation bias.

## Evaluator calibration

*August 27, 2026, 02:30*

Four finals builds had produced the same public score. After eighteen hours on one mechanism, the next request was an ablation of the build history:

> Compare v21 through v40. Isolate the marginal contribution of each addition and check whether the cumulative complexity is justified by measured gains.

The generator overrepresented an unusual scoring regime. At about 02:30 on August 27, the agents corrected that distribution and reran the build history. Eleven of thirty-five mechanisms showed no contribution on the calibrated bank.

<ContestFigure name="ablations" height={460} alt="Removing fitted routes added 24.885 points per test, the upload-feasibility fixes added 8.279, and the remaining changes added 4.215 on 840 calibrated instances.">
  August 27-28 audit, 840 calibrated synthetic instances. Two changes contributed 89% of the measured 37.379-point gain per test. Their contribution to the hidden-test result remains unknown. <a href="https://github.com/seraph27/icpc-huawei-2026/blob/main/docs/POSTMORTEM.md#3-the-lane-lineage-measured-on-one-bank">Measurements</a>.
</ContestFigure>

Removing nineteen routes fitted to recognizable preliminary tests cost about 33 public points. On fresh draws from the observed profile families, the stripped finals build outscored a stronger public-board control by roughly 28 to 38 points per test. Candidate selection now favored that measured generalization over the preliminary ranking.

## Final validation

*August 27-28, 2026*

At 17:20 on August 27, an input sweep found a crash outside the generator's usual machine counts. A subsequent audit with twenty-three agents checked the finals candidate. At 03:01 on August 28, the audit found a search routine taking 22 to 52 seconds against a fifteen-second limit. Restricting it reduced the measured worst case to 0.29 seconds with almost no score loss.

At 03:53:18 PDT on August 28, the final build was submitted. Its source matched the intended file. The contest closed at 04:00. I was asleep.
